# Home Assistant App: Prometheus

[Prometheus][prometheus] is a systems monitoring toolkit: it scrapes
metrics from HTTP endpoints on a schedule, stores them in a local
time-series database, and exposes them through the PromQL query language
and a web UI. Its UI is available straight from the Home Assistant
sidebar via Ingress, and its database lives in `/data`, so Home Assistant
backups of this app capture the full metric history.

## Configuration

Example configuration:

```yaml
scrape_interval: 15
evaluation_interval: 15
retention_time: 30d
retention_size: 4GB
scrape_homeassistant: true
scrape_configs:
  - job_name: node
    targets:
      - 192.168.1.10:9100
      - 192.168.1.11:9100
  - job_name: unifi
    targets:
      - 192.168.1.1:9130
    scrape_interval: 60
    metrics_path: /metrics
    scheme: http
log_level: info
```

### Option: `scrape_interval`

How often targets are scraped, in seconds. Default `15`. Individual jobs
can override it.

### Option: `evaluation_interval`

How often recording and alerting rules are evaluated, in seconds.
Default `15`.

### Option: `retention_time`

How long samples are kept, as a Prometheus duration (`15d`, `12w`,
`1y`, ...). Default `15d`.

### Option: `retention_size`

Optional cap on the database size (`512MB`, `4GB`, ...). Whichever of
time and size is hit first wins. Unset by default.

### Option: `scrape_homeassistant`

When enabled (the default), Prometheus scrapes Home Assistant's own
metrics through the Supervisor API — no long-lived access token needed.
This requires the [`prometheus:` integration][ha-prometheus] to be
enabled on the Home Assistant side; add to `configuration.yaml`:

```yaml
prometheus:
```

and restart Home Assistant. The metrics appear under the
`homeassistant` job.

### Option: `scrape_configs`

A list of additional scrape jobs for the common case of static targets:

- `job_name` (required): name of the job in Prometheus.
- `targets` (required): list of `host:port` endpoints to scrape.
- `scrape_interval`: per-job override, in seconds.
- `metrics_path`: defaults to `/metrics`.
- `scheme`: `http` (default) or `https`.

### Option: `log_level`

Prometheus log level: `debug`, `info`, `warn`, or `error`.

## Advanced scrape jobs and rules

Anything the options above cannot express — relabeling, service
discovery, authentication, alerting and recording rules — goes into
this app's config directory, visible on the host at
`/addon_configs/<repo-hash>_prometheus/` (reachable via the Samba or
SSH add-ons):

- `scrape_configs/*.yaml` — files containing Prometheus
  [scrape configurations][prom-scrape-config] under a top-level
  `scrape_configs:` key, loaded via `scrape_config_files`. A bare list
  without that key fails validation. Example
  `scrape_configs/example.yaml`:

  ```yaml
  scrape_configs:
    - job_name: printer
      static_configs:
        - targets: ["192.168.1.50:9100"]
      basic_auth:
        username: metrics
        password: secret
  ```

- `rules/*.yaml` — Prometheus [rule files][prom-rules] with recording
  and alerting rules.

The configuration (including these files) is validated with `promtool`
on startup; a broken file stops the app with an error in the log rather
than starting Prometheus without it. After editing files you can restart
the app, or POST to `/-/reload` on the API to reload without a restart.

## Using it from Grafana

Add a Prometheus data source in the Grafana app pointing at this app's
internal hostname:

```txt
http://<slug>-prometheus:9090
```

The exact hostname is the add-on slug with `_` replaced by `-`; the slug
is visible in the URL of the add-on's page in Home Assistant (e.g.
`39bd2704_prometheus` → `http://39bd2704-prometheus:9090`). This works
without exposing any port on the host.

To reach the API from outside the internal network (e.g. from another
machine), map port `9090` in the app's network settings — it is
disabled by default. Note that Prometheus has no authentication of its
own and the lifecycle endpoint (`/-/reload`) is enabled, so only expose
the port on a trusted network.

## Backups

The time-series database lives in `/data`, so a Home Assistant backup
of this app includes the full metric history. Extra scrape configs and
rules live in `/addon_configs`, which Home Assistant also backs up.

## Known limitations

- Alertmanager is not bundled; alerting rules evaluate (and are visible
  in the UI) but notifications need an external Alertmanager, which can
  be pointed at via a custom `alerting:` block only through a future
  option. For Home Assistant notifications, querying Prometheus from
  automations or Grafana alerts is usually the simpler path.
- The web UI is served through Ingress from the sidebar; deep links
  generated by Prometheus (e.g. in alerts) use the Ingress path and are
  only valid for logged-in Home Assistant users.
